# 对标拆解与原创迁移 · 使用说明

用于研究一条内容如何让观众进入、理解和行动，然后把方法用于你自己的材料。重点是“为什么这一段对这个人有用”，不是把文字换一遍。

## 怎么调用

> $lany-content-remix-skill 拆解下面这条内容，先找受众和代入场景，再分析结构。我想把表达方式用于自己的案例。请区分证据与假设。

附对标原文/转录或可访问链接；需要迁移时再附自己的事实。只有文字时只做文字分析。

输出包括受众判断、节点拆解表、机制与边界，以及有材料支撑的迁移稿。没有后台指标时不会宣称已经找到爆款原因。

## 完整示例（两份素材均为虚构演示）

对标素材：咖啡教程先展示两杯不同萃取结果，再倒回去解释研磨设置，最后教观众只改一项参数。

我的素材：我给同事改过报销表。原表有多个自由输入的部门名称，汇总时同一个部门分成了几类。后来把部门列改成下拉选项；没有做正式耗时统计。

示例拆解：

| 证据 | 机制假设 | 失效条件 |
| --- | --- | --- |
| 先展示两杯结果 | 让观众先看到差异，产生理解原因的需要 | 差异看不出来，或演示结果被夸大 |
| 回到单个设置 | 把抽象原因落到可操作变量 | 同时改了多个条件，却归因给一个设置 |

迁移草稿：

> 同一个部门，怎么在汇总表里变成了三个？我帮同事检查报销表时，发现部门名称是自由输入的，大家写法不一样。后来我们改成统一下拉选项。下次你遇到重复分类，先看原始列的写法，再检查汇总公式。这个改法处理的是输入不一致，不能修复所有表格问题。

新增价值：自己的工作场景、字段原因和方法边界。沿用的是“先看差异→解释原因→最小动作”，没有照搬咖啡教程的句子。没有数据，因此不写“效率提升50%”。

## 边界

本技能不保证原作流量可以复制，也不会把他人的经历改成你的自述。需要新脚本的口语打磨可用 `lany-short-video-script-skill`；发布后复盘可用 `lany-content-experiment-skill`。
