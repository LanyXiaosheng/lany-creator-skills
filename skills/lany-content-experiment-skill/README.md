# 内容切片与实验复盘 · 使用说明

把工作过程变成选题，把发布反馈变成下一轮改动。适合“每天不知道写什么”和“发了很多却说不清哪里进步”两种情况。

## 怎么用

没有作品时，提供一件正在做的事及实际记录；已有作品时，提供文案、平台、发布日期、观察窗口与数据定义。完整后台不是前提，但缺数据时只能得到有限判断。

输入例如：

> $lany-content-experiment-skill 这是我最近三条教程的文案与数据。都统计发布后48小时，收藏率按收藏人数/播放人数计算。下一轮只想测试先演示结果再讲原理。帮我核对数据，写一张可执行实验卡。

## 完整示例（虚构数据）

| 作品 | 播放人数 | 收藏人数 | 时长 | 开头 |
| --- | --- | --- | --- | --- |
| A | 1000 | 30 | 60秒 | 先定义概念 |
| B | 800 | 32 | 62秒 | 先定义概念 |
| C | 1200 | 48 | 61秒 | 先定义概念 |

正确读法：三条收藏率分别是3%、4%、4%。只能形成约3%–4%的初始描述范围，不能据此证明开头是问题。缺流失曲线，无法判断前几秒留存。

示例实验卡：

- 目标：让需要处理同类表格问题的人更快看懂教程价值。
- 主要改动：首段先展示操作结果，再解释原理。
- 保持项：同类问题、相近时长、相同风格与统计窗口；不能控制的分发差异记入备注。
- 主指标：按相同定义统计48小时收藏率，同时看目标用户的真实问题。
- 预测：可能提升收藏意愿；当前证据不支持承诺具体增幅。
- 判断：一条变好只是信号，继续在相近内容里复验；曝光显著变化或同时换题，则降低可比性。
- 若没改善：检查结果演示是否可理解、是否与目标观众需求匹配，不能直接说“算法限流”。

得到的是实验方案和证据边界，不是凭空给出的增长保证。

## 还能做什么

一件真实任务可以按“步骤、卡点、认识变化”拆成几条独立内容。每条记录受众、证据和可带走的动作；数量看素材，不凑数。有人索要模板可以成为下一轮题目，但不等于已经验证付费需求。

本技能不自动发帖、抓取评论、写长期记忆或删除低表现素材。脚本写作用 `lany-short-video-script-skill`，对标拆解用 `lany-content-remix-skill`。

需要进一步执行或复盘时，阅读 [工作指南](references/methods.md)：包含判断规则、可填写模板、完整虚构练习与方法边界。

## 独立仓库与安装

仓库：[lany-content-experiment-skill](https://github.com/LanyXiaosheng/lany-content-experiment-skill)。独立仓库根目录即技能目录，包含 `SKILL.md`、本说明及 `references/`。

确认目标目录不存在后，可在未设置 `CODEX_HOME` 的默认环境下安装：

```bash
mkdir -p ~/.codex/skills
git clone https://github.com/LanyXiaosheng/lany-content-experiment-skill.git ~/.codex/skills/lany-content-experiment-skill
```

已设置 `CODEX_HOME` 时，将目标改为该目录下的 `skills/lany-content-experiment-skill`。已有同名技能时先比较或备份，不覆盖。客户端发现技能后，使用 `$lany-content-experiment-skill` 调用。

方法指南随本仓库保存和维护。浏览其他技能可进入[合集](https://github.com/LanyXiaosheng/lany-creator-skills)。
